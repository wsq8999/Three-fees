# 智能物业管理系统完整 UI、交互与视觉验收矩阵

版本：2026-08-10  
状态：完整系统实施基线（不是完成证明）  
业务术语：界面统一使用需求正文的“报账点”；代码/API 可继续使用 `billingPoint`，但不得把内部术语直接暴露给用户。

## 1. 使用方法与硬门槛

本文件把《智能物业管理系统需求文档》V4.3 的正文、附录字段合同和原型图转换为可开发、可截图、可自动化的验收基线。需求 DOCX 的关系表包含一个损坏的 `../NULL` 图片关系，因此内容读取以 `word/document.xml`、14 张业务表格和实际可读取的媒体文件为准，不使用会因该关系失败的 `python-docx`。

验收优先级如下：

1. 已确认业务规则与 `docs/PROJECT_MANUAL.md` 中的 Commander 决策；
2. 本文件对应的原型图和页面交互；
3. DOCX 附录 A 的 73/198/42/39 列合同；
4. 原型中的示例姓名、城市、数量和金额只控制表现形式，不是固定业务数据。

最终测试开始前必须同时满足：

- 本文“完成登记”中的每一项都有前端代码路径、后端/OpenAPI 资源（如适用）、自动化测试 ID 和截图证据；
- 不存在 `PlaceholderView`、“建设中”“即将上线”、只弹成功提示但不改变状态的正式业务入口；
- 所有可点击控件都有成功、加载、禁用、失败与恢复语义，不得使用无响应按钮；
- 页面在对应原型的原始视口及 1366×768 下与原型保持一致；只有原型未定义的加载、空、错误、禁用、无权限和窄屏状态允许按同一设计语言补齐；
- `docs/testing/FULL_FLOW_TEST_STRATEGY.md` 的通道 A 连跑 3 轮、通道 B 连跑 2 轮后，Commander 才能把本文状态由“实施基线”改为“已验收”。

状态标记：`SPEC` 表示设计与交互已明确；`TODO` 表示尚待实现/复验；`PASS` 只能由 Commander 在读取代码和证据后填写。本文初始不把任何旧占位页标记为完成。

## 2. 角色、权限与数据范围

| 角色 | 可见菜单与能力 | 强制数据范围 | 禁止项 | 对齐测试 |
|---|---|---|---|---|
| `SUPER_ADMIN` | 工作台、报账点管理、稽核报告管理（生成报告/历史报告）、标杆规则管理、用户管理；拥有全部业务操作 | 江苏省全量，可按地市/区县筛选 | 不得绕过正式报告唯一性、字段校验或更正原因 | `E2E-AUTH-01`、`E2E-USER-01` |
| `CITY_USER` | 除用户管理外的全部业务菜单；可导入、导出、稽核、AI、报告和历史查询 | 登录账号绑定的唯一城市；城市选择器只显示/固定该城市 | 用户管理入口不可见且接口返回 403；修改 URL/API 城市参数不得越权 | `E2E-AUTH-02` |
| 未登录 | 仅登录页及静态资源 | 无业务数据 | 受保护路由跳转 `/login?redirect=...` | `E2E-AUTH-01` |
| 已停用账号 | 登录页可见 | 无 | 登录失败，不能恢复旧会话 | `E2E-USER-01` |

权限必须同时由前端路由/菜单和后端数据范围约束，隐藏按钮不能代替后端授权。全部账号的临时初始口令由运行环境安全注入；界面只使用密码型输入，不在源码、Mock、Markdown、日志、截图或浏览器持久化中写出实际值。

## 3. 全局框架与视觉一致性

### 3.1 桌面壳层

- 登录后采用固定左侧导航、顶部栏/面包屑、浅灰主内容背景和白色卡片；1366×768 时侧栏约 200 px、顶栏约 55 px，实际边界以同尺寸原型叠图为准。
- 侧栏顺序固定：工作台、报账点管理、稽核报告管理（生成报告、历史报告）、标杆规则管理、用户管理（仅超管）；底部是“收起导航”。当前菜单以浅红底、左侧红色指示条和红色图标/文字表现。
- 顶部左侧显示主页图标和面包屑；右侧显示圆形头像、用户显示名和下拉箭头。下拉菜单必须提供“修改密码”和“退出登录”。
- 内容区卡片白底、细灰边框/轻阴影、8–16 px 圆角；正文以深蓝黑为主，说明文字为蓝灰色。主要动作使用原型红色体系（基准 `#F5222D`，原型有渐变时保留红色渐变），成功为绿色、警告为橙色、失败/超标为红色、特殊超标标签可使用原型紫色。
- 不得自行引入深色侧栏、巨幅装饰图、玻璃拟态或另一套组件风格。图标线宽、按钮高度、圆角、阴影和间距必须由设计令牌统一控制。

### 3.2 表格、表单与弹窗

- 查询区标签在输入框上方；字段从左到右、从上到下严格按本文顺序。查询为红色主按钮，重置为白色次按钮。
- 业务宽表默认每页 10 条，可切换 20/50；固定左侧选择框/关键标识列和右侧操作列，中间横向滚动。固定列必须有不透明白底，不能透出滚动内容。
- 表格页底部左侧显示“已显示/已选择 X–Y 条，共 Z 条”，右侧为每页数与分页；横向滚动条位于表格与分页之间且始终可操作。
- 弹窗背景遮罩为中性半透明深灰；标题和关闭按钮在顶部，取消在底部右侧主按钮左边。弹窗尺寸和按钮位置以相应原型的同视口边界为准，缩放误差不得靠内容挤压掩盖。
- 只读完整字段弹窗内部独立滚动，页面底部固定操作区不随弹窗滚动；Esc、右上角关闭和取消不得提交数据。

### 3.3 截图对照门

每张实际存在的原型都要由 Playwright 在原图原始视口截取同一状态，并保留“原型、实现、50% 透明叠图”三份证据。动态数字、姓名和时间可遮罩，以下内容不可遮罩：

- 侧栏/顶栏边界、导航层级、面包屑、卡片分组和主内容起始位置；
- 表格列顺序、行密度、固定列、分页与滚动条；
- 弹窗外框、标题、分区、字段顺序、按钮顺序和按钮锚点；
- 主色、状态色、背景层次、字号层级、圆角与主要间距；
- 所有原型可见按钮、页签、输入框、标签、说明文字和状态标签。

同尺寸叠图中，主要布局锚点允许误差不超过 12 px；不得缺失或增加会改变业务层级的可见控件。抗锯齿和系统字体造成的像素差异可以人工复核，但不能用其豁免位置、字段顺序或颜色体系偏差。

#### 稽核分析

页面顶部输入摘要顺序：当前账期（含自然日数）、实际总耗电量、实际日均耗电量、实际报账金额。下方“标杆计算结果”表列序：标杆项目、对比账期/取值依据、参考日均/月平均、标杆阈值、本期实际值、结果、超标比例。三行顺序固定为历史日均电量同比标杆、历史日均电量环比标杆、额定标杆总量；右上显示最终结论。

| 项目 | 适用前置 | 计算/展示 | 不适用与边界 | 测试 |
|---|---|---|---|---|
| 本期实际 | 当前有效电表行 | 实际总耗电量=有效电表“分摊后度数”之和；日均=总量÷本月自然日数；金额=有效去重缴费单金额之和 | 实际缺失时最终为“—”，不得用 0 替代缺失 | `E2E-AUDIT-01`、`E2E-AUDIT-02` |
| 参考月资格 | 至少 1 张当前有效去重缴费单，且所有参与汇总单均审核通过 | 仅合格自然月可供同比/环比选择 | 任一参与单待审/拒绝，整月不具参考资格 | `E2E-AUDIT-02` |
| 同比 | 上一年度同一自然月合格；A/B/C 完整且 B>0 | C=参考月日均；A=本月额定总量÷本月天数；B=去年同月额定总量÷去年同月天数；K=max(1,A/B)；阈值=C×K×1.20；本期日均>阈值为超标 | A/B/C 缺失或 B≤0 为不适用；闰年按各自自然日数 | `E2E-AUDIT-01`、`E2E-AUDIT-02` |
| 环比 | 当前月之前结束日最近的合格自然月；A/B/C 完整且 B>0 | C=参考月日均；A=本月标杆月平均；B=参考月标杆月平均；K=max(1,A/B)；阈值=C×K×1.20；本期日均>阈值为超标 | 不要求固定上一月；缺月时找最近合格月；A/B/C 缺失或 B≤0 不适用 | `E2E-AUDIT-01`、`E2E-AUDIT-02` |
| 额定标杆 | 当月日标杆通过完整性校验 | 总量=1 日至月末有效日值之和；实际总耗电量>总量为超标；比例=(实际-总量)/总量×100% | 总量=0 且实际=0 为正常；总量=0 且实际>0 为超标并显示“阈值为0”，比例不伪造为无穷数 | `E2E-AUDIT-01`、`E2E-AUDIT-02` |
| 最终结论 | 至少一项适用 | 任一适用项超标→超标；全部适用项正常→正常；最大超标比例取三项最大有效值；超标类型按唯一/多项组合 | 三项均不适用或实际缺失→“—” | `E2E-AUDIT-01` |
| 自动重算 | 四类任一激活批次变化 | 只重算受影响的报账点+月份，同步工作台、列表、详情、候选和草稿输入 | 已生成正式报告保持当时快照，不被自动重写；需要变化必须走更正 | `E2E-AUDIT-02`、`E2E-REPORT-03` |

高精度规则：金额、度数、阈值和比例在 API 中使用十进制字符串；计算过程使用十进制类型，舍入只发生在展示层并采用统一规则。比较使用未格式化值，不能先四舍五入再判定。

## 9. 端到端业务流程

### 9.1 首次空库到正式报告

1. 超管或市级用户登录，工作台显示真空库状态；
2. 进入报账点管理，按 01→04 依次导入同城市同自然月数据；
3. 每步观察 durable 任务成功，第四步后形成月度快照、当前账期和稽核结果；
4. 在列表查询正常、超标、待审核和不适用记录，检查横滚与详情 5 个视图；
5. 对“超标+待生成”进入工作稿，执行问答（正文不变）、修改（新增版本）、图片分析（新增版本）、恢复（再新增版本）；
6. 生成为唯一正式报告，待办移除，历史列表出现，Word 可下载、PDF/结构化正文可预览；
7. 返回各来源时状态完整恢复。

覆盖：`E2E-IMPORT-01`、`E2E-BP-01`、`E2E-AUDIT-01`、`E2E-DRAFT-01`、`E2E-REPORT-01`。

### 9.2 错误导入、整批替换和自动重算

1. 上传类型错误/缺列/行值错误文件，定位到文件/工作表/行/列，失败批次不激活；
2. 修正后重试成功；
3. 对已有激活批次重新导入，确认整批替换，旧批次标记被替代；
4. 验证列表/详情/工作台/报告候选重算，已经生成的正式报告保持快照；
5. 进程/页面刷新后任务状态一致。

覆盖：`E2E-IMPORT-02`、`E2E-AUDIT-02`、`E2E-STATE-01`。

### 9.3 历史报告导入

1. 历史报告列表打开导入弹窗；
2. 选择真实报账点及符合条件的历史超标账期；
3. 上传 Word，任务转换 PDF，生成报告编号；
4. 列表查看、PDF 预览、原 Word 下载；
5. 不符合候选条件、重复“报账点+账期”和转换失败均不得创建空报告。

覆盖：`E2E-REPORT-02`。

### 9.4 报告更正

1. 从最终报告详情发起，原因留空时禁止；
2. 系统生成报告进入编辑/AI 流程，人工导入报告进入更正版 Word 上传；
3. 成功后编号不变、最终正文/Word/PDF 同时更新；
4. 页面无正式版本记录，旧最终文件无下载入口；
5. 失败/并发时原最终报告保持可用。

覆盖：`E2E-REPORT-03`。

### 9.5 用户与权限

1. 超管新增、编辑、重置、停用、启用一个市级用户；
2. 停用时不能登录，启用后恢复；
3. 市级用户只见绑定城市，修改 URL/API 城市参数也不能越权；
4. 用户管理菜单不可见，直达页面/API 都被拒绝；
5. 超管刷新会话、修改密码、注销均正确。

覆盖：`E2E-AUTH-01`、`E2E-AUTH-02`、`E2E-USER-01`。
