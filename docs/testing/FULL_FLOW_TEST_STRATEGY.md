# 完整系统上线验收策略

本文规定“功能全部完成后”的上线验收口径。当前系统验收只接受真实前后端链路：浏览器访问 Vue，Vue 调用 Spring Boot API，Spring Boot 连接 MySQL 和文件目录。不得再以纯前端 Mock、H2 演示库或固定假成功接口作为完成依据。

## 1. 入口条件

- `docs/requirements/FULL_SYSTEM_ACCEPTANCE.md` 中所有正式功能项均标记为已实现，且有代码路径和测试 ID。
- 前端业务路由不存在占位页、仅提示“建设中”的按钮或无状态变化的假成功处理。
- `FULL_SYSTEM_ACCEPTANCE.md` 的逐图索引全部落实；实际存在的 24 张原型图都有页面/弹窗状态和截图断言。包内缺失的 image3 只按正文补齐，不凭空猜测视觉稿。
- 后端公开 OpenAPI 覆盖用户、导入、任务、报账点、稽核、草稿、报告、文件与更正资源；Java DTO 与前端运行时类型一致。
- 四类字段目录分别精确为 73、198、42、39 项，源字段名、列序、类型、业务分组和导出顺序有自动检查。
- 所有异步流程具备提交、查询、成功、失败、重试和进程重启恢复语义；worker 不再是空角色。
- 前端 lint、格式、类型、单元/组件测试和生产构建通过；后端格式、静态、架构、迁移、单元/集成和覆盖率门禁通过；AI Schema 与测试通过。

## 2. 验收环境原则

- 数据库必须使用真实 MySQL `three_fees`，并通过 Flyway 迁移到最新版本。
- 文件根必须使用真实受控目录，报告 Word、PDF、导入原文件和导出文件均落在该目录下。
- 前端不得启用 Mock API 插件、Mock 路由或演示模式；所有业务数据必须来自后端 API。
- AI 能力由 Java 后端按环境配置调用；本地验收没有密钥时，只能标记 AI 外部调用未验，不得改用前端演示数据替代。
- 账号口令、数据库密码、模型密钥只从本机环境变量或未提交配置读取，不写入源码、Markdown、日志或测试报告。

## 3. 最终测试通道

### 通道 A：静态与构建门禁

验证代码质量和发布构建：前端类型检查、单元测试、生产构建；后端迁移、单元/集成测试和可启动性检查。此通道不等同于业务验收，但必须先通过。

### 通道 B：真实链路浏览器验收

启动 Spring Boot API/worker、MySQL 和 Vue，通过浏览器访问真实 REST API；验证 Cookie/CSRF、RBAC、任务状态、导入解析、稽核、文件生成、报告状态变化、下载与审计追溯。验收过程中产生的数据进入真实目录与真实数据库，验收前后必须有记录和可追溯清理方案。

## 4. 必跑业务场景

| ID | 场景 | 核心断言 |
|---|---|---|
| E2E-AUTH-01 | 超管登录、刷新、注销 | 会话恢复；注销后受保护路由不可访问 |
| E2E-AUTH-02 | 地市用户数据隔离 | 只见绑定地市；用户管理 403；篡改城市参数无效 |
| E2E-USER-01 | 新增、编辑、重置、停用、启用用户 | 表单/状态/权限正确；停用账号不能登录 |
| E2E-IMPORT-01 | 顺序导入四类有效文件 | 卡片逐步开放；任务完成；批次/快照/当前账期建立 |
| E2E-IMPORT-02 | 错误文件、重复和整批替代 | 行列错误可定位；失败不切换；成功重导替代旧批次 |
| E2E-EXPORT-01 | 列表与详情四类导出 | 未选择时禁用/提示；单类 Excel；多类 ZIP；权限范围正确 |
| E2E-BP-01 | 报账点查询、宽表、详情与返回 | 查询/分页/每页数/横滚恢复；三主页签和二级视图完整 |
| E2E-AUDIT-01 | 同比、环比、额定标杆 | 正常/超标/不适用、最大比例和最终类型正确 |
| E2E-AUDIT-02 | 边界与自动重算 | 闰年、缺失、B≤0、零标杆、多单审核、精度和重导重算正确 |
| E2E-DRAFT-01 | AI 问答、修改、图片分析、版本恢复 | 问答不改正文；修改/图片/恢复创建版本；失败保留当前稿 |
| E2E-REPORT-01 | 生成正式报告 | 从待办移除；报告编号唯一；Word 下载与 PDF 预览可用 |
| E2E-REPORT-02 | 历史报告导入 | 候选账期正确；原 Word 保存；PDF 可预览；报告编号不与已有目录冲突 |
| E2E-REPORT-03 | 系统/人工报告更正 | 原因必填；编号不变；最终正文/Word/PDF 覆盖；审计追溯准确 |
| E2E-RULE-01 | 标杆规则只读核验 | 三条规则、计算链、示例、边界和快照说明可切换 |
| E2E-STATE-01 | 空态、失败、重试与刷新 | 无伪造数字；错误可恢复；刷新后 durable 状态一致 |

## 5. 运行轮次

1. 通道 A 每次发布前完整执行一次，失败不得进入浏览器验收。
2. 通道 B 至少以超管和两个不同地市用户完成一轮真实业务链路。
3. 在 1366×768 执行所有核心页面视觉/溢出断言，并在窄屏下检查导航与表格可操作下限。
4. 对原型原始尺寸不同于 1366×768 的弹窗场景，另以对应原始比例截图核对导航层级、信息分组、字段顺序、表格密度、弹窗尺寸和按钮位置。
5. 任一失败必须修复后重新跑受影响业务链路，不能只用局部接口成功宣称通过。

## 6. 最终证据

- 记录 Git 状态、工具链版本、测试命令、退出码、用例数、耗时和失败修复摘要。
- 记录 Flyway 版本、MySQL 连接目标、文件根、后端健康检查、前端访问地址和前后端代理/API 联通结果。
- 保存关键页面截图、后端测试报告、覆盖率、OpenAPI/字段目录一致性报告和发布包 SHA-256；不提交验收产生的业务文件。
- 视觉证据索引必须能从 image1、image2、image4-image25 逐项定位到最终截图；任何功能正确但明显偏离原型布局的页面仍判为失败。
- 明确区分：本地真实链路验收、预生产 Windows Server 验收、生产上线。三者不得混写。
