# 完整系统全流程测试策略

本文规定“功能全部完成后”的最终系统测试门。实现阶段仍执行单元、契约和静态门禁，但只有本文件的入口条件全部满足后，才启动最终浏览器全流程并给出系统完成结论。

## 1. 入口条件

- `docs/requirements/FULL_SYSTEM_ACCEPTANCE.md` 中所有正式功能项均标记为已实现，且有代码路径和测试 ID。
- 前端业务路由不存在占位页、仅提示“建设中”的按钮或无状态变化的假成功处理。
- `FULL_SYSTEM_ACCEPTANCE.md` 的逐图索引全部落实；实际存在的 24 张原型图都有页面/弹窗状态和截图断言。包内缺失的 image3 只按正文补齐，不凭空猜测视觉稿。
- 后端公开 OpenAPI 覆盖用户、导入、任务、报账点、稽核、草稿、报告、文件与更正资源；Java DTO、前端运行时类型和 Mock 响应一致。
- 四类字段目录分别精确为 73、198、42、39 项，源字段名、列序、类型、业务分组和导出顺序有自动检查。
- 所有异步流程具备提交、查询、成功、失败、重试和进程重启恢复语义；worker 不再是空角色。
- 前端 lint、格式、类型、单元/组件测试和生产构建通过；后端格式、静态、架构、迁移、单元/集成和覆盖率门禁通过；AI Schema 与测试通过。

## 2. 临时假数据原则

### 2.1 纯前端 Mock 通道

- Mock 状态只存在 Vite/测试进程内存，进程退出即丢失。
- 每个 Playwright 用例开始前调用测试专用 reset 能力恢复确定性场景；该能力只在 `mock`/`test` 模式编译或注册，生产构建不可访问。
- 上传文件由测试运行时生成到测试临时目录；下载结果只进入 Playwright 临时下载目录。
- 不读取、不写入 MySQL，不复用 DEMO 的真实材料。

### 2.2 真实 API 通道

- Java 使用 `e2e` profile、H2 `mem` 数据源和随机数据库名；测试进程退出后数据消失。
- 文件根使用带随机标记的系统临时目录；只允许测试脚本在验证绝对路径、随机目录名和专用标记后清理。
- Python AI sidecar 使用 deterministic fake provider，不调用真实付费模型。
- 账号口令、CSRF 和内部服务令牌由测试编排器在进程环境中随机生成并注入，不写源码、Markdown、日志或测试报告。
- 测试前验证目标 JDBC URL 为 H2 `mem`，文件根位于受管临时目录；任何生产 MySQL URL 或正式文件根都会使测试立即失败。

## 3. 最终测试通道

### 通道 A：纯 Mock 全交互 E2E

验证页面和交互本身：按钮、弹窗、页签、校验、加载、空态、错误、分页、横向滚动、路由、返回状态恢复、角色菜单和下载行为。此通道速度快，可重复跑多轮。

### 通道 B：Vue + Java + Python + H2 全链路 E2E

由编排脚本启动 AI fake sidecar、Java API/worker 和前端 preview，通过浏览器访问真实 REST API；验证 Cookie/CSRF、RBAC、任务状态、导入解析、稽核、文件生成和报告状态变化。全部进程与临时目录在 `finally` 中回收。

## 4. 必跑业务场景

| ID | 场景 | 核心断言 |
|---|---|---|
| E2E-AUTH-01 | 超管登录、刷新、注销 | 会话恢复；注销后受保护路由不可访问 |
| E2E-AUTH-02 | 地市用户数据隔离 | 只见绑定地市；用户管理 403；篡改城市参数无效 |
| E2E-USER-01 | 新增、编辑、重置、停用、启用用户 | 表单/状态/权限正确；停用账号不能登录 |
| E2E-IMPORT-01 | 顺序导入四类有效文件 | 卡片逐步开放；任务完成；批次/快照/当前账期建立 |
| E2E-IMPORT-02 | 错误文件、重复和整批替代 | 行列错误可定位；失败不切换；成功重导替代旧批次 |
| E2E-EXPORT-01 | 列表与详情四类导出 | 未选择时禁用/提示；单类 Excel；多类 ZIP；权限范围正确 |
| E2E-BP-01 | 报账点查询、宽表、详情与返回 | 查询/分页/每页数/横滚恢复；三主页签和二级视图完整 |
| E2E-AUDIT-01 | 同比、环比、额定标杆 | 正常/超标/不适用、最大比例和最终类型正确 |
| E2E-AUDIT-02 | 边界与自动重算 | 闰年、缺失、B≤0、零标杆、多单审核、精度和重导重算正确 |
| E2E-DRAFT-01 | AI 问答、修改、图片分析、版本恢复 | 问答不改正文；修改/图片/恢复创建版本；失败保留当前稿 |
| E2E-REPORT-01 | 生成正式报告 | 从待办移除；报告唯一；Word 下载与 PDF 预览可用 |
| E2E-REPORT-02 | 历史报告导入 | 候选账期正确；原 Word 保存；PDF 可预览；生成报告编号 |
| E2E-REPORT-03 | 系统/人工报告更正 | 原因必填；编号不变；最终正文/Word/PDF 覆盖；无正式版本页 |
| E2E-RULE-01 | 标杆规则只读核验 | 三条规则、计算链、示例、边界和快照说明可切换 |
| E2E-STATE-01 | 空态、失败、重试与刷新 | 无伪造数字；错误可恢复；刷新后 durable 状态一致 |

## 5. 运行轮次

1. 通道 A 全场景至少连续运行 3 轮，每轮 reset 后结果一致。
2. 通道 B 全场景至少连续运行 2 轮，每轮使用新的随机内存库和临时文件根。
3. 以超管和至少两个不同地市用户复跑权限敏感场景。
4. 在 1366×768 执行所有核心页面视觉/溢出断言，并在窄屏下检查导航与表格可操作下限。
   对原型原始尺寸不同于 1366×768 的弹窗场景，另以对应原始比例截图核对导航层级、信息分组、字段顺序、表格密度、弹窗尺寸和按钮位置。
5. 任一失败必须修复后从该通道第一条场景重新跑完整轮次，不能只重跑失败用例后宣称通过。
