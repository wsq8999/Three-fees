# MySQL 数据库规范

## 1. 版本与字符集

- 生产目标 MySQL 8.4 LTS，所有迁移兼容 MySQL 8.0.31。
- 默认字符集 `utf8mb4`，排序规则由建库脚本统一，不在不同表混用。
- 事件时间以 UTC 写入 `DATETIME(3)`；展示转换为 `Asia/Shanghai`。自然月、账期使用独立年月字段或月首 `DATE`，不从 UTC 时间猜测。

## 2. 命名

- 表、列、索引和约束使用 snake_case，小写英文。
- 表名使用单数业务名：`app_user`、`business_task`；关联表表达双方：`app_user_role`。
- 主键 `id`；外键 `<entity>_id`；业务编码 `<entity>_code`。
- 普通索引 `idx_<table>__<columns>`，唯一索引 `uk_<table>__<columns>`，外键 `fk_<table>__<target>`。

## 3. 类型

- 内部主键默认 `BIGINT`；公开任务/文件可增加不可枚举的 UUID/ULID 业务标识。
- 精确数值使用 `DECIMAL(p,s)`，禁止 `FLOAT/DOUBLE` 存金额和用电量。
- 状态使用受应用与迁移共同约束的 `VARCHAR` 代码，不使用 MySQL `ENUM` 锁死演进。
- 布尔值使用 `BOOLEAN`（实际映射 `TINYINT(1)`），列名以 `is_` 开头时保持全库一致。
- JSON 只用于完整保留动态原始导入字段；核心查询、关联和约束字段必须类型化成列。

## 4. 通用字段与并发

- 可变业务表包含 `created_at`、`created_by`、`updated_at`、`updated_by`、`version`。
- `version` 用于乐观锁；更新必须验证受影响行数。
- 批次、报告等需要保留历史的资源使用明确状态/失效时间，不用物理删除。
- 真正允许删除的临时记录也必须由受控清理任务执行并记录范围。

## 5. 索引与查询

- 唯一业务约束必须落到数据库唯一索引，不能只靠 Java 查询后判断。
- 高频过滤采用符合最左前缀的组合索引；避免为每列机械建单列索引。
- 索引设计同时考虑地市数据范围，例如 `(city_code, period, status)`。
- SQL 明确列名，分页排序追加稳定唯一键，避免翻页重复/遗漏。

## 6. Flyway

- 文件名：`V<version>__<english_description>.sql`；已在共享环境执行的迁移不得修改，只能新增迁移修正。
- DDL、约束、索引和种子字典都通过迁移；环境相关凭据绝不进入迁移。
- 迁移应可在空库一次执行，并有从上一个发布版本升级的验证。
- 大表破坏性迁移必须拆分为兼容的扩展、回填、切换、清理阶段。

## 7. 导入数据

- 每类导入先写批次和 staging；校验完成后在事务中激活新批次、失效旧批次并触发重新计算。
- 原始行保留 `source_row_number`、`raw_payload` 和稳定摘要，便于追溯；错误行与激活数据隔离。
- 计费点编码等可能带前导零的字段必须按字符串处理。
- 不信任 Excel 显示格式；日期、科学计数、公式、空白和编码要有明确解析策略与测试。

## 8. 备份与恢复

- 数据库备份必须与文件元数据/文件目录处于可解释的一致时间窗。
- 试运行目标为每日备份、7 个日备 + 4 个周备；RPO 24 小时、RTO 4 小时。
- “备份成功”不等于可恢复，发布前必须在隔离库执行恢复演练并记录校验结果。
