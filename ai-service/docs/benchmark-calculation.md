# 标杆指标识别与复算边界

本文说明当前Agent如何处理三费报告中的标杆截图，以及后续接入三费原始数据时应遵守的计算边界。目标是避免把“历史同比/环比标杆”误解为普通同比增长率，同时保留每项结论的证据追溯能力。

## 1. 当前版本已经支持的复算

当前Word通常只提供三费系统已经生成的实际值、标杆范围、是否超标和超标率截图。在这种输入条件下，程序只做截图结果一致性校验：

1. 高于上限超标判断：`实际值 > 标杆上限`。
2. 高于上限时的超标率：`(实际值 - 标杆上限) / 标杆上限 × 100%`。
3. 将程序结果与截图显示的超标结论、超标率比较。
4. 截图通常只显示有限小数位，因此超标率允许 `0.1` 个百分点的展示舍入差异。

这一层只能证明截图中的数字相互一致，不能表述成“程序已经重新生成或验证三费标杆上限”。

## 2. 当前版本明确不做的计算

历史日均电量同比、环比标杆的完整生成依赖以下三费原始数据：

- 历史同期或上一笔审核通过缴费的报账电量与缴费天数；
- 本次及历史缴费期的额定功率标杆和缴费天数；
- 同比历史记录是否审核通过、当前是否首期缴费；
- 逐日主设备功率、站点类型、空调功率及城市月度空调运行时长；
- 规则生效日期、计算精度和最终舍入方式。

这些输入未进入Agent状态前，模型和程序都不得猜测A、B、C，也不得用普通增长率公式替代标杆生成公式。

## 3. 业务适用状态

- `verified`：至少完成实际值与标杆上限判断，且截图结果没有冲突。
- `unverified`：缺少实际值或标杆上限，无法完成截图结果复算。
- `conflict`：截图超标率或超标结论与程序复算不一致，必须人工处理。
- `not_applicable`：材料明确说明首期缴费、没有审核通过历史等业务条件，因此该项不参与比较。

单独出现“-”但没有原因时只能判为`unknown/unverified`，不能擅自认定为不适用。

## 4. 完整标杆规则的后续实现原则

完整A/B/C标杆生成应由确定性规则服务完成，Kimi只负责从材料中识别输入和证据位置。规则至少按城市、指标类型、版本和生效时间管理；泰州月度空调运行时长属于城市规则，不能放入历史案例记忆或由模型自由推断。

在业务确认以下口径前，不启用完整标杆生成：

1. `A/B < 1`时是否确定按系数`1`处理，并继续应用20%上浮。
2. 缴费期存在无功率数据日期时，是否使用“有值日平均数 × 缴费总天数”。
3. 三费系统使用的中间精度、最终舍入位数和截图展示位数。
4. 江苏其他城市是否存在不同的空调运行时长或上浮比例。

## 5. 与城市记忆的关系

标杆公式属于确定性业务规则，不属于RAG历史记忆：

- 规则用于计算和校验数字，并按城市和有效期版本化。
- 历史案例和人工纠错记忆用于判断超标原因，并继续严格城市隔离。
- 规则变更不会删除历史记忆；历史记忆也不能覆盖确定性计算规则。
