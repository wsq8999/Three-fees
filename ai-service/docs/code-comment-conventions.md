# 代码注释规范

本项目面向长期维护和业务共同评审，新增代码默认使用中文注释。

## 必须说明的内容

- 模块、类、接口和服务的业务职责。
- 江苏13市数据隔离边界和报账点归属校验。
- 数据库表、关键字段、唯一约束和复合外键存在的原因。
- LangGraph节点的输入、输出、状态变化和证据来源。
- Kimi调用范围、Schema校验、图片读取方式和失败降级行为。
- 事务何时提交、回滚，以及失败记录为什么需要保留。
- 前端表单数据来源、异步调用顺序和用户可见错误。

## 注释质量

好注释应回答“为什么”，例如：

```python
# 先提交pending，使长时间模型调用期间数据库可以展示真实进度。
self.session.commit()
```

不要把语法机械翻译成没有额外信息的文字，例如：

```python
# 给count加1。
count += 1
```

代码逻辑变化时必须同步修改注释。OpenAPI生成类型等自动生成文件不手工修改，避免重新生成后丢失。
